# v5 优先级分析：从第一性原理推导「什么是必要的」

*角色：项目负责人。本文档回答一个问题：在候选功能池中，哪些是**必要**的（不做则产品根基有缺口），哪些只是**有益**的（做了更好），并据此排定 v5 执行顺序。*

## 1. 目标回顾：我们在玩什么游戏

产品的不可替代价值 = **「记忆被永久保存，且这一承诺可被独立验证」**。

- 北极星指标：**月度缅怀行为数**（献花 + 点烛 + 留言 + 回访）——当它持续大于新建数，产品进入复利区间
- 商业模型：按量存储计费（含免费额度）+ 情感溢价产品；成本一次性（永久存储买断），收入先于成本发生
- 体验基线（用户已明确）：**与传统应用一致**——登录即拥有，看不到密码学

## 2. 第一性原理：产品成立的四个支柱

把产品拆到不能再拆，它依赖且仅依赖四件事同时成立：

| 支柱 | 内涵 | 崩塌形态 |
|---|---|---|
| **P1 信任** | 承诺为真：数据真的永久、访问真的不丢、机制真的可验 | 「说好的永久呢？」——一次失信毁掉全部沉淀 |
| **P2 沉淀** | 记忆持续流入：创作无摩擦、内容形态足够承载感情 | 空间建了不再更新，护城河停止加深 |
| **P3 回访** | 缅怀者年复一年回来，且回来时有事可做、有人同在 | 低频产品彻底沉寂，传播断裂 |
| **P4 经济** | 每字节存储的收入 ≥ 成本，滥用被拦截 | 服务端代付被刷爆，或规模越大亏损越大 |

**必要性检验**：一个功能是「必要」的，当且仅当**在当前阶段**，它的缺失会让某个支柱出现真实缺口。其余一切，按杠杆率排序。

## 3. 候选项逐项检验

### 判定为「必要」（v5 立即做）

| # | 候选 | 支柱 | 第一性分析 | 工作量 |
|---|---|---|---|---|
| N1 | **演示模式明示**（devnet 横幅） | P1 | 当前部署写入 devnet，数据约 60 天被清除——而首页承诺「永久」。**这是现存唯一的实质性失信点**，必须在切换 mainnet 前对用户明示 | 小 |
| N2 | **生产级限流**（DB 后端） | P4 | 现限流为实例内存级；Vercel serverless 每次调用可能是新实例 ⇒ 生产环境限流形同虚设，而**存储费由我们代付**——滥用直接烧钱。上线前必要 | 中小 |
| N3 | **账户双通道绑定**（邮箱 ↔ 钱包） | P1 | 无密钥化后，**账户即一切**（余额、托管密钥、守望）。单一登录凭证 = 单点故障：邮箱失访或钱包丢失即失去全部。绑定第二通道是账户连续性的最低保障 | 中 |
| N4 | **缅怀回执**（空间动态邮件周报） | P3 | 北极星是缅怀行为，但**创建者今天感知不到任何缅怀**——献花点烛无人知晓，回访闭环断裂。「有人为 TA 点了一支烛」是本产品最强的回访理由，没有之一 | 中 |

### 判定为「高杠杆」（v5 做，排在必要项之后）

| # | 候选 | 支柱 | 分析 | 工作量 |
|---|---|---|---|---|
| H1 | **永恒套餐**（一口价存储包 $29/2GB、$99/10GB） | P4 | 按量计费机制正确但决策心理错位：纪念场景用户要的是「一次安放，永久安心」，不是盯着余额。一口价降低决策焦虑、提高客单与毛利。基于现有免费额度机制扩展，改动可控 | 中 |

### 判定为「延后」（明确触发条件，暂不做）

| 候选 | 支柱 | 为什么现在不必要 | 触发条件 |
|---|---|---|---|
| 端到端加密托管 + 社交恢复 | P1 | 平台信任模型 = 传统应用的信任水平，用户已接受；E2E 是增强而非缺口，且与「无感体验」有张力（口令即新的可丢失物） | 出现付费用户明确诉求，或作为高端套餐差异点 |
| 手机号 OTP / 微信登录 | P2 | 邮箱 + 钱包已覆盖注册路径；国内短信/微信需主体资质与供应商，环境暂不具备 | 正式面向国内运营时（需备案主体） |
| 大文件直传（>3.5MB 视频） | P2 | 有真实价值（视频是最强情感载体），但工程复杂（Irys 余额授权 + 绕过服务端的审核链重构），且尚无用户证据表明 3.5MB 上限是当前流失点 | 用户反馈/数据表明视频受限是主要抱怨 |
| 时间胶囊 / 未来信 | P2/P3 | 强差异化功能而非根基；依赖「定时解密」的托管密钥设计，应在 E2E 托管方案定型后一并做，避免返工 | v6 主打功能候选 |
| 站内搜索增强 | P3 | 链上索引只支持标签精确匹配；当前内容量下页内过滤足够 | 空间数 > 数百 |
| 登录服务迁移（Clerk 等） | — | 已评估（见 PRODUCT-ROADMAP §0.5）：现阶段自研已覆盖，扩张期再接 | 需要社交一键登录/MFA 时 |

## 4. v5 执行顺序

```
46. 本文档（优先级基线）
47. N1 演示模式横幅：非 mainnet 部署时全站明示，杜绝失信
48. N2 生产级限流：资金敏感路径（上传/发布/记录）改 DB 滑动窗口
49. N3 账户绑定：邮箱账户可绑钱包、钱包账户可绑邮箱，任一通道可登录
50. N4 缅怀回执：每周将空间收到的花/烛/留言汇总邮件给守护者
51. H1 永恒套餐：一口价存储包（额度制），与按量充值并存
52. v5 综合验证与文档更新
```

判断依据一句话版：**先堵信任与经济的缺口（N1/N2/N3），再接通回访闭环（N4），然后优化变现（H1）；一切「更酷」但不护住支柱的候选，全部延后并写明触发条件。**

## 5. 风险与未决

- N3 绑定流程需防「身份抢占」：被绑定的邮箱/钱包若已属他人账户，必须拒绝而非合并（合并涉及余额/托管归属，风险大于收益）
- N4 依赖链上查询：每用户每周一次、按空间聚合，当前规模成本可忽略；空间数上千后需要索引缓存
- H1 定价：套餐按字节额度（而非余额）入账，与免费额度同一消耗通道，避免出现两种「钱」的心智
- Mainnet 切换本身是运营动作（充值主网钱包 + 改环境变量），代码已就绪；N1 横幅确保切换前的诚实
